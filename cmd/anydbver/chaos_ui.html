anydbver chaos — help

Inject network faults into the containers of a deployed namespace, live. All shaping is applied inside each container's network namespace; nothing is installed in your containers.

Nodes

  • Colour = state: green running · orange paused · red stopped.
  • Click a node to Pause (freeze the process), Kill (hard stop), Unpause, or Start it again.

Links

  • Click any line between two nodes to shape that link. Faults are symmetric (applied in both directions).
  • Ctrl-click (or ⌘-click) additional links to select several at once and apply the same fault to all of them.
  • Apply = latency / loss / effects · Partition = 100% packet loss both ways · Clear = remove it.

Link parameters

  • Delay — added latency, e.g. 100ms. Note: a ping round-trip ≈ 2× delay (applied each direction).
  • Jitter — random variation on the delay, e.g. 20ms.
  • Loss % — random packet drop rate. Loss corr % makes the loss bursty (drops cluster, like a real flaky link).
  • Corrupt % — random bit errors · Duplicate % — packets sent twice · Reorder % — packets delivered out of order.
  • Rate — bandwidth cap, e.g. 1mbit.
  • Ranges: any field accepts min-max (e.g. 3-6, 50-200ms) — a random value is picked when applied.

Flux — drifting fault values

Header toggle (default every 8s). Normally a link's value is rolled once, when you apply it. Flux re-rolls every ranged value on a timer, so the network conditions keep wandering instead of staying constant — a realistic flaky/congested link rather than a clean fixed degradation.

  • Only affects ranges: delay=50-250ms drifts (80ms… 140ms… 210ms…); delay=100ms never changes.
  • To see it: apply a ranged link, toggle Flux on, then re-run Measure a few times — the latency/loss keeps changing.

Chaos monkey — random node failures

Header toggle, click to cycle off → pause → kill. Every interval it picks a random running node, disrupts it, and auto-recovers it after half the interval — then picks another, forever. You don't choose which node or when, so it tests whether the cluster survives losing an arbitrary member at an arbitrary moment (failover, re-election, replica promotion).

  • pause — freezes a node (docker pause): it hangs but keeps its connections (like a GC pause / frozen VM), then unpauses.
  • kill — hard-stops a node (docker kill): a crash / power loss, then restarts it.
  • Never acts when fewer than 2 nodes are running, so it can't take the whole cluster down.
  • Independent of links — Monkey disrupts whole nodes, Flux re-rolls link faults. You can run both at once.

Flapping link

In a link's panel, set Down/Up seconds and Start flapping — the link auto-cycles between partitioned (down) and healed (up). Drawn as a dashed orange line.

Safety

  • Clear all faults removes everything immediately.
  • All faults clear automatically when you press Ctrl-C in the terminal, or after the inactivity timeout (--ttl).
